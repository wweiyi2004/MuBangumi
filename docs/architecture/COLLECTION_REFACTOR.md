# 收藏加载与编辑拆分：第二阶段

## 职责

`SessionController` 原先仍直接负责收藏分页、切换线路后的刷新、编辑队列、章节快照及撤销。本轮将这些操作迁入收藏模块，页面调用入口保持兼容。

| 模块 | 职责 |
| --- | --- |
| `CollectionLoader` | 首次加载、普通刷新、线路切换后全类型加载、分页发布、请求失效和加载状态 |
| `CollectionEditor` | 收藏与章节编辑、同一作品的操作顺序、本地修订号、队列落盘、章节快照与撤销、失败记录操作 |
| `CollectionEditView` | 编辑器可读写的四项页面数据：收藏列表、正在编辑的作品、撤销提示、最近章节修改 |
| `CollectionReconciler` | 上一阶段提取的纯合并规则，供加载与编辑共同使用 |
| `SessionController` | 登录身份及批次、首页准备、线路设置、模块组装和现有页面接口 |

收藏模块不导入会话状态或页面。编辑器通过注入的账号读取函数校验身份，通过 `CollectionEditView` 读写收藏相关数据；不维护第二份收藏列表，不更改登录字段、加载标识或同步计数。加载器从编辑器读取最新收藏及本地修订，通过独立的进度回调发布结果。

## 生命周期与兼容性

- 加载请求同时绑定账号身份、登录批次和加载批次；网络返回、本地队列读取和逐类型加载后均重新核对。
- 新刷新、退出、切换线路或销毁会使旧加载失效。等待本地队列期间发生的变化也不会被漏掉。
- 编辑仍先写入持久队列再反馈成功。旧账号已开始的写入保留原归属，排队等待的旧操作执行前会再次检查身份。
- 章节修订与撤销记录由编辑器管理；退出时清理内存修订，原来的持久化队列保留规则不变。
- 同名账号重新登录后，旧的失败队列查询也会被丢弃；旧编辑完成快照写入后不能更新新的登录。
- 收藏快照是可选缓存，写入失败不产生未处理的异步错误，也不阻断已加载数据。
- 未改数据库表、队列载荷、OAuth 流程、账号凭据存储格式或页面调用参数；无需数据迁移。
