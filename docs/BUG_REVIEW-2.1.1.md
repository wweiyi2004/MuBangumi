# v2.1.1 缺陷检查

检查日期：2026-09-08。基线为已发布的 `v2.1.1`，修复尚未发布。

## 已复现并修复

| 级别 | 触发方式与原行为 | 修复 |
| --- | --- | --- |
| P1 | 私信校验收件人 A 后改填 B，发送仍使用 A 的 `msg_receivers`；A 的慢校验结果也可覆盖 B | 收件人改变立即使旧表单与旧请求失效；发送前核对表单绑定的收件人；发送准备期间合并请求并锁定输入 |
| P1 | 切换网站账号后，已打开的私信仍显示旧内容；旧账号取得的表单可能配上新账号 Cookie 发出 POST | 私信表单绑定取得它时的认证会话，发送前检查；迟到的旧响应被拒绝；会话/写信页面在登录变化时清除旧内容、表单与草稿并停用发送 |
| P2 | 从会话 A 切到 B 后，B 加载失败，界面仍保留 A 的表单且可发送 | 切换话题立即清除旧表单；失败时显示错误并停用发送，保留话题切换与重试入口 |
| P2 | Windows 退出时后台 Cookie 清理尚未完成，新登录已写入 Cookie，随后旧清理删除新登录 | Cookie 清理和注入按顺序执行；退出继续异步清理，但后续登录注入会等待清理完成 |
| P2 | 320 像素宽度、1.8 倍字体下，写信页“收件人已确认”提示横向溢出 | 提示文字使用可伸缩区域并允许换行 |

会话比较只使用认证 Cookie：普通验证码 Cookie 刷新不会清空私信草稿或使同一登录下的表单失效。回复完成后还会检查页面和请求是否仍有效，避免对已离开的页面继续更新。

## 证据与验证

- 修复前新增回归中，5 个 UI 场景、3 个私信服务场景及 1 个 Windows Cookie 场景失败。模拟发送只记录请求，不向真实用户发送私信。
- 主要回归位于 `test/pm_flow_safety_test.dart`、`test/pm_service_test.dart`、`test/website_cookie_bridge_test.dart`。
- `flutter analyze --no-pub lib test`：无问题。
- `flutter test --no-pub --reporter expanded`：414 项全部通过，较发布基线增加 15 项；补充验证清空已确认收件人不会发给旧收件人，连续点击发送只校验并发送一次。
- 已发布 v2.1.1 的 Android APK、Windows ZIP 和校验文件与 GitHub 附件摘要一致；两个安装包 ZIP CRC 校验通过，未包含 `.dart_tool`、本地数据库或密钥文件。

## 检查范围

本轮重点检查私信、登录会话异步交错、近期布局改动及 v2.1.1 发布附件。未使用真实账号操作官网，也没有真机复现网络环境；测试通过不代表所有页面或第三方网站路径均已覆盖。

历史 v2.1.0 Windows 附件中已知的本地数据库目录问题不影响本次 v2.1.1 附件校验；本轮未替换历史发布附件。
