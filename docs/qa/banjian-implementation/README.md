# 无音频番键会实现与试用

日期：2026-09-18。已从审核设计稿接入真实服务与本地持久化，未接入音频。

## 怎么用

1. MuBangumi → **我的 → 设置 → 实验性功能 → 番剧鉴赏**。
2. 选择「本机局域网」，启动服务，创建番键会。
3. 添加番剧：搜索名称 / 条目 ID，或勾选本机动画收藏导入。选中的收藏会携带封面来源，由服务后台缓存；离线时先保存文字，恢复联网后补齐，也可点击「补全封面」重试。
4. 点击「进入管理」，直接进入软件内的原生管理台。本机已经取得管理会话，无需再次输入密码；其他设备仍可在浏览器打开服务地址的 `/admin`，输入管理密码。原生管理台右上角菜单保留「浏览器管理入口」。
5. 在番单里开始一部番剧，点击「邀请参与」分享二维码 / 链接。还没有活动时会先要求命名并创建。
   局域网模式下邀请面板同时显示两张码：① Wi-Fi 二维码（主持人首次填写名称和密码，保存在本机安全存储；系统相机扫码即可入网），② 参与二维码。连接在线服务器时只显示参与码。
   主持端现在自动推荐热点 / Wi-Fi / 有线地址，降低 VMware 等虚拟网络的优先级；通常不需要手动选择 IP。连接问题时才展开「连接问题 / 切换网络」。推荐基于本机网卡，不能替代另一设备实际访问验证。
6. MuBangumi「扫一扫」直接打开原生参与页；系统相机等扫码工具打开网页。原生默认 Bangumi 昵称，网页首次询问显示名。已登录 Bangumi 的原生参与者会带上头像，由服务端只从 `lain.bgm.tv` 下载缓存后显示在入场名单；网页参与者显示名字首字。
   同一二维码保留普通 HTTP/HTTPS 网页入口，并在片段中携带最多 7 个同端口私有 IPv4 备选地址。MuBangumi 并行寻找服务、核对活动后显示昵称确认页；浏览器使用二维码的主地址。在线 HTTPS 入口不携带 LAN 备选地址。这里不会自动切换 Wi-Fi，也不会扫描整个网段。
7. 管理端可以暂停、截止、切换轮次、公布统计、把短评墙对全员开放、隐藏评论、查看提交名单、结束活动以及导出 CSV / JSON。
8. 参与者给本轮评分后即可看到本轮短评墙（主持人隐藏的评论除外），先打分再看别人的评价；主持人的开关用于让未评分的人也能看到。新短评会在原生和网页的参与页、管理页以弹幕形式飘过一次；系统开启「减少动态效果」时不显示弹幕。弹幕在主持人来得及隐藏之前就会出现。
9. 「结束活动」等同于公布所有已开始轮次的统计。参与者可在参与页点「查看整场汇总」（或详情里的「汇总」），看到按均分排名的整场番单、每部评分人数和自己的分数；进行中只汇总已公布轮次。主持人在原生管理台菜单「整场汇总」或网页「评分结果」顶部查看，大屏展示同样包含汇总。

参与页返回上一页后，首页会出现临时返回入口；选择「退出活动」隐藏入口，保留同设备的参与身份。主持人关闭管理网页不会停止服务；「结束活动」和「停止服务」是两个操作。

跨网使用：部署独立服务后，在「连接服务器」填写 HTTPS 根地址和管理密码。部署说明见 [服务端 README](../../../packages/banjian_server/README.md)。目前提供服务代码、部署模板和 Windows 可执行包，**没有替用户部署公网主机**。

- 「进入管理」已连接完整 Flutter 原生界面，包含创建/改名、选番、顺序调整、切番、暂停/继续/截止、公布结果、短评墙开关及隐藏、成员、历史、邀请更新、结束活动和 CSV/JSON 导出。网页入口保留，两端共享同一活动和服务端权限校验。
- 原生管理端使用 WebSocket 接收实时状态，HTTP 轮询作为恢复路径。实时消息和稍后返回的旧 HTTP 快照同时到达时，不允许旧规则版本覆盖较新状态；确认框期间活动被其他管理员更新时，会取消过期操作。
- 载入提示采用品牌粉色播放符号、圆角字符边框和移动小点。首次读取自动滑入；在列表顶部下拉露出，达到阈值松手刷新；完成显示勾号后收回，失败显示重试提示。不会在每次实时推送时重播。开启减少动态效果时不循环帧。
- 已接入原生服务页、管理台、参与页、选番查询，以及网页管理/参与的首次载入、刷新按钮和触摸下拉。下拉未达到阈值取消；重复刷新合并为一次；输入内容保持。

### 管理端与参与端一屏流

- 管理主屏采用最大 1440×900 的固定工作区，随可用窗口适配；番单路线、当前番剧、评分进度环、均分/人数、短评与整场进程同屏。长番单和短评只在各自面板滚动；详细统计、历史活动、成员等在覆盖面板打开，主屏不跳转。较矮窗口将分布图收进详细统计，保留当前轮次操作。
- 网页与原生参与主屏只展示当前轮次、选分、短评输入和固定提交按钮。评论墙、统计、往期番单通过抽屉查看；输入时收起封面与评分格，发送按钮保持可见。长短评在输入框内部滚动。
- 网页实时更新保留同一个输入框节点及焦点，避免每次推送重建输入框；切番时保留原轮次草稿。原生端也补测了切番前不足 300ms 的草稿保存，避免防抖计时被新输入覆盖。
- 网页主题采用软件的粉色强调色、深浅背景和文字配色，提供浅色/深色/跟随系统切换。软件打开管理页时携带当前主题；网页自己的后续选择保存在浏览器中。
- 浏览器检查直接断言页面高度、内容区滚动量和提交按钮的位置：参与端 390×844、360×640、352×700、768×900，以及管理端 1440×900、1280×720、1100×800、1280×640、1024×640 的主屏操作无需滚动。10 组原生界面测试通过，包括 360×640、键盘占用 300px、大字体、深色、自动换址和切番草稿。
- 大字体或更小窗口保留内容区的可访问滚动，不裁掉功能、不缩小点击目标；此轮尚未连接真机验证微信软键盘，只验证了浏览器视口和原生键盘占位场景。

### 番键会封面导入修复

- 根因：收藏导入只写入文字快照和空 `cover`，没有保留来源或安排下载；当前活动的 6 个条目均因此缺少封面。另修正原生参与页自动换址后仍从扫码原地址读取图片的问题。
- 导入保留选中条目的官方封面 URL，后台下载后写入独立封面缓存，再向管理/参与端推送；提交番单、评分和评论不等待图片网络请求。
- 启动服务会补齐现有活动的缺失封面；旧快照没有 URL 时按条目 ID 获取官方封面。失败保留文字，提供重试入口，并定期重试当前活动。
- 仅允许官方封面域名和图片路径；不跟随跳转，限制文件大小，验证 JPEG/PNG/WebP 文件头。更新封面采用事务读取当前活动，只修改图片字段，不覆盖同步到来的评分或管理设置。
- 新增 5 项封面缓存/修复测试通过（服务包合计 23 项）。原生界面补充了自动换址后的图片 URL 测试（8 组界面检查通过）。
- 本机现有活动已先备份再补全，6/6 张封面均通过运行中服务的 HTTP 接口读取，并通过图片解码检查；与备份对比，所有非封面字段保持一致。备份保存在应用支持目录的 `banjian/backups/`。

### 同名新场误分享旧二维码修复

- 问题：在浏览器结束旧场并创建同名新场后，服务设备仍可能保留旧场选择，继续提供已结束活动的二维码。此外，历史列表曾按 SQLite 替换写入后的 rowid 排序，旧记录更新会被误当成最新活动。
- 修复：服务设备默认跟随进行中的活动；主动查看历史时明确标记，并提供「返回当前活动」。历史列表改为进行中优先、创建时间排序。
- 生成邀请前刷新并核对服务端；已结束活动的邀请链接/二维码接口返回 409。已经打开的邀请面板在活动结束或切换后撤下旧二维码。
- 网页和原生参与页明确提示「这张二维码对应的活动已结束，请扫描主持人正在进行的活动的新二维码」，不把旧活动偷偷恢复，也不将旧活动评分迁移到新场。
- 回归：新增用例先在旧实现上复现“期望新场 ID、实际旧场 ID”，修复后通过。服务测试增至 18 项；浏览器完成“旧码失效→同名新场→新码入场”的完整检查，15 组原有布局检查保持通过。

### 自动寻找地址增量验证

- 新增 9 项测试：普通 URL / 旧二维码兼容、候选地址限制、Wi-Fi 与虚拟网卡排序、首地址无响应后的并行选择、错误服务拒绝、不同活动拒绝、失败提示及统一超时。
- 服务端增加随机挑战接口 `/api/locate`，通过活动邀请秘密的 HMAC 响应确认房间。候选探测只发送活动 ID 和随机挑战；确认成功后才发送邀请秘密读取预览，尚未发送参与凭据或 Bangumi 凭据。

## 尚未实测的边界

- 当前没有连接 Android / iOS 真机。Android 已成功编译，但手机热点互访、锁屏、厂商后台策略、通知权限拒绝后的实际行为仍需真机验收。
- 没有完成原计划中的 **50 客户端连续两小时真实局域网** 验收；本轮两分钟回环结果不能替代该指标。
- Windows 防火墙未自动放行，也没有修改路由器；学校 Wi-Fi 客户端隔离、热点容量和实际可达性要以设备互访为准。
- iOS 不承诺后台托管活动；本轮没有在 macOS 上编译 iOS。
- 公网部署模板尚未实际部署到服务器，本机 Docker Linux 引擎未启动。独立 Windows CLI 可以构建并已验证服务协议。
