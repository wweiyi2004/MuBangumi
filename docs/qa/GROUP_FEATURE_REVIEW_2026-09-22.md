# 小组功能客户端专项复查

本轮沿小组列表、成员状态、详情、网页加入/退出、话题读取及现有发帖/回复兼容路径检查。使用合成响应与组件测试，没有读取用户私密小组内容、加入/退出真实小组或发布真实帖子。

## 已修复并复现的问题

1. **附属请求导致整个详情失败**：原先资料、成员、管理员、话题用一次全成功等待，任一附属请求失败就丢弃有效资料。现在主资料仍必须有效，附属失败分别标记，单项等待有上限。失败的话题列表明确显示未加载，而不是“还没有话题”。失败标记与缓存一起保存。
2. **成员身份被日期影响**：有合法 membership.uid、但 joinedAt 为 0 或缺失时，原实现误判未加入。现在成员记录与展示日期分开，保留未加入状态和旧构造数据兼容，不把创建者 ID 或任意布尔值反转为成员资格。
3. **我的小组残留旧账号内容**：列表未直接监听服务账号变化。现在切换账号立即废弃旧请求，清空列表并读取新账号数据；内容偏好变化也刷新相关小组列表/详情。服务层同时拒绝过时的账号、小组成员状态和内容偏好响应。
4. **分页偏移使用解析后数量**：被过滤的数据行仍占用服务端 offset，原实现会重复请求、漏后续数据。列表及缓存均保留原始行数，全页暂时无法解析时仍允许继续翻页，不直接显示“没有小组”。
5. **加入/退出后的旧请求与列表滞后**：网页返回后先废弃之前的小组请求缓存，再读取成员资料；退出详情页时刷新上一级列表。加入/退出入口限制并发打开，并展示初始化异常。
6. **私密话题网页兜底未带登录、登录页被显示为空正文**：公开读取失败后，现在在需要时使用核验过的网页会话读取固定官方话题路径。Cookie 不会发往话题对象自带的任意网址；登录页、验证码和不可见内容会明确报错，登录过期提供“补充账号验证”。旧账号请求不会转为使用新账号 Cookie 的读取。

## 保持的边界

- 官方 P1 的成员参数问题仍由官方修复。本地发帖/回复只在明确成员拒绝时尝试经典网页；未知响应或 5xx 不盲目追加一次 POST。
- 小组正文不可见仍可能是服务端权限、审核、删除或网络问题，客户端不会通过放宽权限假装成功。
- 回复在提交后失去响应时仍需核对实际话题内容；本轮未声称验证了真实发布结果。前一轮新增发帖回执及持久待确认机制保持有效。
- 没有执行真实加入/退出；本地测试验证刷新和状态隔离，不代表对指定小组完成线上验收。

## 验证

新增 `group_state_regression_test.dart`、`group_screen_state_test.dart`、`group_topic_read_recovery_test.dart`，并运行既有社区、解析、分页、账号与网页兼容测试。首轮新增的四个服务/解析案例在旧实现上均失败，修复后通过。

最终运行 `tool/verify_all.ps1 -Mode Full`，以生成的源码指纹报告为准。软件不自动加入或退出任何小组。
