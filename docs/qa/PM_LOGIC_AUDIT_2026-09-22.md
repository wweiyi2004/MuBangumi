# 好友私信逻辑复审

审查范围：应用账号与网页登录绑定、同时打开收发件箱、网页捕获、草稿恢复、读取与刷新、提交回执和持久发送队列。基于用户持续反馈间歇不可用及要求仔细检查逻辑开展；没有使用真实账号发信。

## 已确认并修复的问题

| 级别 | 缺陷与触发条件 | 修复 |
| --- | --- | --- |
| P1 | HTTP 拒绝登录后立即 reload：reload 增加 generation，使已经接受的失效写入被跳过，随后读回旧的有效绑定 | 接受失效后先加入串行持久化队列，再通知监听器；普通 reload 不能取消该写入。写盘失败时，当前控制器也记住被拒绝的请求快照 |
| P1 | 草稿持有旧身份结果，失效后用同一 Cookie 再调用 bindVerifiedUser，可重新绑定；甚至未检查当前应用账号归属 | 新建绑定须匹配验证时的 requestKey、当前账号及允许的状态；拒绝过期、挑战、检查中状态。已经有效核验的同账号续期仍可复用草稿 |
| P1 | POST 返回空白 HTTP 200 或普通表单，缺少成功证据，却被记录为已发送 | 要求明确发信成功提示或同源官方消息结果页跳转。证据不足返回 PmDeliveryUncertain，持久队列保留任务等待核对，不自动重放 POST |
| P2 | 冷启动时第一个请求尚在读取会话，第二个请求因 expectedUser 已设置而跳过等待，误报缺少登录 | 同一账号的初始化共享 attachment future，所有请求等待完成 |
| P2 | 强制核验或浏览器捕获尚未完成，普通请求先命中旧有效缓存，将 checking 改回 available | 检查在途验证优先于缓存；验证 future 在发布 checking 状态前登记，覆盖同步监听器重入；浏览器捕获也共享在途结果 |
| P2 | 浏览器捕获验证失败，磁盘写入 unverified，内存仍保留继承的 verifiedUserId，后续请求重新使用旧绑定 | 失败捕获在内存和磁盘统一为未验证；不匹配的浏览器账号仍不覆盖之前保存的账号 |
| P2 | 刷新失败邮箱时，尚未收到结果就清除 needAuth，界面短暂显示可用 | 只有成功读取后才解除邮箱的登录阻塞 |
| P2 | 第一条信息提示导致 parseSubmissionError 提前返回，忽略后续错误提示 | 遍历全部网站提示，错误优先；消息正文里的成功文字不作为发送回执 |
| P2 | 队列在调用 service 前就标记 submitted，service 尚未发起 POST 就因登录失败中止，也被误标为结果不确定 | 明确区分 PmPreflightAuthException：尚未提交的任务等待验证后恢复；真正发起 POST 后的未知结果仍须核对 |

## 当前转换规则

| 触发 | 结果 |
| --- | --- |
| 同账号并发启动 / 正在核验 | 等待同一个操作，不提前发出可用状态 |
| 有效绑定且无正在核验 | 使用当前绑定；单独的 challenge Cookie 更新不改变草稿归属 |
| 当前请求收到真实登录拒绝或挑战 | 先排队撤销绑定，再通知界面；历史请求不能撤销新核验结果 |
| 新网页身份核验成功 | 按顺序持久化新快照，再显示可用 |
| 旧草稿身份迟到 | 不得为被拒绝的 Cookie 新建绑定，也不得绑定到另一个应用账号 |
| GET 临时失败 | 沿用上一轮的有界重试、限流等待和已有记录保留 |
| POST 缺少成功证据 | 保留为需要核对的任务，不报告成功、不自动重新发送 |

## 验证与边界

- 最初 7 项精确时序回归在修复前全部失败，修复后通过。
- 扩展覆盖同步监听器重入、网页捕获等待、写盘失败、失效后新核验胜出、相同账号续期、过时草稿证明、旧版身份元数据、空白回执、结果页同源约束和错误提示优先。
- 全量 Flutter 测试 **1,275 项通过**；静态分析、架构边界及依赖图自测通过。全量首次运行还指出无可信来源的新 Cookie 不应覆盖磁盘，已保留原有拒绝策略：只有临时失败的待核验捕获，或当前会话明确失效，才按相应策略写盘。
- 本轮未改变发送队列“结果不确定时不自动重发”的原则。由于没有用户现场响应，仍不能宣称所有手机现场失败都已复现。若官方改变发送回执页面，可能转为需要核对，而不会静默标成已发送。
- 存储本身持续写入失败时，运行中的控制器能防止重读恢复旧绑定；无法声称在存储完全不可写时仍能持久化失效状态到下一次进程启动。
