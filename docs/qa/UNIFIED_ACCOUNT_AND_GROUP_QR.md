# 统一账号与小组二维码（2026-09-17）

承接 [整体改造清单](../architecture/UNIFIED_ACCOUNT_PLAN.md)，包含已认可的导航布局。

## 使用入口

- 登录页：内置或已保存 OAuth 配置可用时，主按钮为“登录 Bangumi”；手动 Token 和自定义配置仍在高级选项。
- 我的 → 设置 → Bangumi 账号：集中查看收藏 / 进度账号以及聊天 / 小组操作的可用状态，可重新核验或补充验证。
- 消息 → 扫一扫：识别旧好友码、官方用户链接、小组官网链接。手机走摄像头，Windows 沿用从图片识别。
- 小组详情 → 右上角二维码：展示、保存、分享小组码，也可复制规范化的官网链接。
- 扫到小组只打开原生详情，不自动加入。加入仍由用户在已有官网登录流程中完成；回到应用会刷新成员状态。

## 账号处理

- API 会话继续由原来的 SessionController / SessionCredentials 管理，保留自动刷新合并、可信离线恢复与退出写入屏障。
- WebsiteSessionController 区分缺失、待核验、核验中、可用、过期、账号不一致、网页挑战、网络暂不可用和清理失败。
- Cookie 身份核验使用独立请求，仅携带 Cookie，不使用 API Authorization 来替代网页登录身份。
- 官网用户标识与 API 用户 ID 对齐；不匹配时阻止网站操作，保留 API 登录。错误候选 Cookie 不覆盖已核验的持久化会话。
- 旧记录即使保存了 verifiedUserId，也必须重新核验；新的版本化身份绑定带核验时间，短时复用，同一轮并发核验合并。
- 仅有主题或挑战 Cookie 不构成已核验登录；候选认证 Cookie 存在也只表示可尝试核验。
- 私信读取 / 发送、小组官网回退与加入入口统一使用核验门禁。服务端明确过期或挑战会反馈到统一状态。
- API 换号、Cookie 变化、退出等使旧回调失效；小组详情、私信列表和打开的网页也随之失效。
- 补登录窗口按账号合并；验证完成后恢复原会话和已保存的草稿。原生小组回退提交前再次确认账号与认证 Cookie 没有变化。
- 退出后的浏览器 Cookie 清理有等待屏障和失败重试，Windows 清理三个官方站点别名。清理错误日志仅含错误类型与调用栈，不输出原始 Cookie 异常详情。

## 二维码边界

- 小组码载荷为 `https://bgm.tv/group/{slug}`，不是加组命令，也不携带登录凭据。
- 仅接受明确的官方域名、标准 HTTP(S) 端口及用户 / 小组路径；拒绝伪装域名、用户信息段、操作路径、编码分隔符和异常载荷。
- 保留 `mubangumi:friend:v1:` 老格式；图片识别先提取原始载荷，再统一区分好友和小组。
- 私密小组先读取摘要，不因尚未加载讨论列表而丢失加入入口；实际权限仍由 Bangumi 决定。
- 没有调用真实加组、发信、发帖或其他写操作来测试。
