## 已确认的问题

v2.1.0 Windows ZIP 混入 `.dart_tool/sqflite_common_ffi/databases/` 下的 5 个 SQLite 数据库，包含开发测试账号身份、515 条收藏快照和本地新番表记录。原代码发现本机凭据后先显示 SQLite 的 `session_last_user`，再请求 `/me`；网络验证临时失败时可能保留错误身份。已确认本地数据外发，没有据此认定开发者有效账号凭据外泄。

污染 ZIP 的 SHA-256：`9b006c75a3b21972974f20a423cf3e5a0d33d1cd3ed46e9ad20c62455de73a29`。

## 修复与预防

- `/me` 成功后，将身份与当前安全存储凭据绑定；离线启动只信任同一凭据记录中的身份。更换账号或退出清除绑定，刷新凭据保留绑定，迟到写入受登录代次及凭据匹配检查保护。
- Windows 可丢弃缓存移至应用用户目录的 `cache-v2`，不导入可执行文件旁的旧账号缓存。其他平台通过缓存数据库升级清理旧账号缓存。
- 新番表、RSS、草稿和待同步修改等独立持久数据不在本次清理范围内。
- OAuth 完成但账号验证暂时失败时保留内存中的验证信息，支持重试；可信身份恢复不再被慢速刷新阻塞。
- `.gitignore` 已覆盖本地 OAuth 配置、构建和发布目录；补充环境变量文件、SQLite 与 WebView 资料规则。公共示例配置保留。
- CI 检查已跟踪的个人配置和运行数据，包括被改名的 SQLite 文件。检查器只覆盖已知文件类型与布局，不是任意源码凭据扫描器。
- 打包从全新暂存目录按运行文件范围复制，校验暂存目录与最终 ZIP，拒绝数据库、浏览器资料、凭据文件、异常路径、重复项及链接。校验通过才生成最终可分发文件名。
- 打包补齐 Visual C++ 运行库，以支持未安装开发工具的 Windows 环境。

## 追加：实际登录反馈与线路验证

用户测试 build 13 时反馈登录显示“Access Token 无效或过期”，因此人工验收未通过。用户随后确认：选择第三方线路，点击一键登录，完成网页授权后发生该错误。

2026-09-11 用专门构造的无效测试令牌进行只读请求，未使用真实用户凭据：

| 请求 | 未携带令牌 | 携带测试令牌 |
| --- | --- | --- |
| 官方 `/v0/me` | 401，`need Login` | 401，`access token has been expired or doesn't exist` |
| 第三方 `/v0/me` | 401，`need Login` | 401，`need Login` |

观察结果与第三方路径未正确转发 Authorization 一致；仅靠该测试不能确认中间服务的内部实现。旧客户端把所有 401 映射成令牌过期，且让账号验证走内容线路，会把线路问题误当成凭据失效。

修复后的身份验证直接请求官方 `/v0/me`，携带 Bearer 与 no-store 请求头，不更改用户选择的内容线路。第三方 401 作为可重试的线路验证错误处理，不触发凭据刷新或清除；官方明确拒绝的凭据仍不允许进入账号。HTTP 错误分类按请求实际目标域名判断，避免绝对官方 URL 被 Dio 的第三方 baseUrl 误分类。依据：[Bangumi 官方授权说明](https://github.com/bangumi/api/blob/master/docs-raw/How-to-Auth.md)。

新增 7 项自动回归，覆盖两条内容线路下的实际请求 URL 与 Bearer、代理 401、官方 401、刷新后的令牌以及保留凭据/授权续试。另以真实 BangumiApi 和无效测试令牌执行网络探测：选中第三方线路时身份请求仍到达官方，官方拒绝无效令牌，探测通过。用户已确认修复后使用官方线路能够登录自己的账号；第三方线路下新版本的实际登录仍待复测。

当前 build 14 候选包已重新校验归档和二进制一致性，并替换本机预览窗口供用户复测。用户随后确认官方线路登录成功，发布继续保持草稿，等待其余人工验收。

## 追加：Windows 字体一致性

用户反馈整体文字忽粗忽细，未指定某一处控件。主题此前仅指定中文回退字体，没有设置 Windows 主字体，中英文可能分别使用不同字体；浅色与深色主题的按钮、标签也使用了不同字重。

build 15 在 Windows 使用系统 Microsoft YaHei UI 作为主字体，并给显式控件样式设置相同的字体及回退规则；两种主题的按钮和标签统一使用 600 字重，正文使用 400，保留标题层级。没有把本机字体文件加入源码或发布包。

用本机安装字体进行离屏渲染，检查浅色/深色主题在 100% 与 140% 字号下的中英文、数字、按钮、标签和输入框样张；两项渲染检查通过，样张无缺字或溢出。离屏样张不代替原生应用主观观感验收。独立分支 419 项测试通过、静态检查无问题；原开发分支另有 34 项现有界面与大字号回归通过。字体实际观感仍待用户在新版窗口确认。
