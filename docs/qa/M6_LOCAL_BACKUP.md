# M6 本地备份与导入验收记录

日期：2026-09-08。状态：数据层检查点 `7aae41f` 已实现及验证；应用内入口、设备互导和安装产物未完成，未发布。版本仍为 `2.1.1+11`，本阶段未上传 Release 或 Shorebird 补丁。

## 当前实现

- 单个 UTF-8 JSON 文件，格式标识 `mubangumi-backup`、版本 `1`，包含账号 UID／用户名、UTC 导出时间、类别及 SHA-256 校验值。严格验证字段、类型、记录标识、引用、排序、大小及嵌套深度。文件不超过 16 MiB，记录总数不超过 50,000，搜索历史最多 12 条。
- 校验值基于递归按键排序的 JSON，数组顺序保留；校验值用于发现损坏，不是签名。当前格式没有加密，草稿和备注属于明文内容。后续界面应明确说明，并默认关闭两个草稿类别。
- 数据白名单包含新番表、RSS 源与过滤规则、备注／屏蔽、置顶、浏览偏好／搜索历史、推荐反馈、社区草稿和私信草稿。不会附加数据库文件、凭据、Cookie、可重放队列、RSS 条目缓存、提醒 ID 台账或草稿删除记录。
- 新番表、RSS、备注／屏蔽沿用现有设备共享范围；置顶、浏览偏好、反馈和草稿按当前账号读取。不同 UID 的文件被拒绝；同 UID 改名时，用户名键重新绑定当前用户名。
- 旧版新番表缺失的三个提醒字段在导出读取时补为关闭、20:00；其余损坏或未知字段仍报错，不静默删除安排。

## 冲突与恢复行为

合并保留本地冲突项，加入不存在的记录；同季度内保留原作品的所有字段，只追加新作品。置顶、搜索、RSS 规则和私信草稿保留本地顺序后追加导入项。搜索合并超出 12 条时，计划明确计入未加入项。

覆盖仅替换选择的类别，包括清除这些类别中备份没有的记录。未选择类别和其他账号的数据保持原样。预览保存所选数据的摘要，执行时在事务中重新读取、核对并重新生成计划；预览后有变化就拒绝继续。

SQLite 协调数据库使用持久文件，将最多六个个人数据库作为固定别名附加。所有参与者必须使用 DELETE 回滚日志，并启用 FULL 同步；不允许内存主库、重复路径或 WAL。导入日志和个人数据在同一个事务中提交。日志只记录账号、文件校验值、模式、类别和时间，不记录正文。

这遵循 SQLite 对多文件原子事务的条件，见 [ATTACH 官方说明](https://www.sqlite.org/lang_attach.html) 与 [原子提交机制](https://www.sqlite.org/atomiccommit.html)。当前故障实验覆盖事务提交前强制退出，不等同于对真实设备断电或任意存储硬件故障的验证。

RSS 本地 ID 在导入时重新分配，源与规则引用同步转换；源和规则未改变时保留并重映射原缓存，规则或匹配顺序改变时清除相应缓存及抓取验证信息。备份本身不包含 RSS 条目。

社区草稿库升级至 v2，原有文本保留。社区及私信导入更新草稿版本，删除保留无正文的版本记录，旧编辑器迟到的保存／清理会被拒绝。社区草稿读取失败时禁止编辑和发送，重试成功后恢复；保存冲突保留当前输入，并提供不保存关闭。
