## 验证方法

最终本地验收使用：

```powershell
./tool/verify_all.ps1 -Mode Full
```

每次执行将结果保存到 `.dart_tool/verification/<run>/results.json`，包含源码指纹、每步状态和日志路径。该目录为本机证据，不随源码分发；当前报告不以一个固定测试数量代替这份实际结果。

编辑期间已用针对性测试验证：数据库恢复、所有写动词的账号切换、验证码/未知提交不重放、诊断隐私与容量，以及发布脚本的源码/版本/哈希/验收保护。网站审计在更新后为 0 条；它仍需在每次依赖升级后重新执行。

首次完整验证发现同名 Shorebird 缓存 SDK 的 Android 引擎元数据与普通构建不匹配，因此改用独立的官方 3.44.7 SDK，并将官方 framework/engine 提交一同固定和校验；原有全局 SDK 与 Shorebird 缓存保留。

## 明确边界

- 本机无连接的 Android 真机，未对真实账号完成登录/私信/小组验收；acceptance.example.json 保持 pending。
- iOS 构建与手动模拟器工作流已配置，尚需推送后在对应 CI 环境执行。配置就绪不等于云端已通过。
- 普通 Debug 本地构建不需要发布凭据。Shorebird 命令沿用既有行为，但新增发布前记录校验；本轮仅用模拟 CLI 测试，不调用真实上传。
- 补丁记录中的 SDK 是本地工具信息。实际引擎由 Shorebird 安装基线决定，回执阶段必须核对补丁编号、服务端 ID、通道和实际编译产物；不会自动伪造这些字段。
- 本轮先收拢认证请求策略，没有一次性拆完全部大型页面和社区业务；后续按功能继续迁移，保留既有回归与架构约束。
- 原有未提交改动没有被擅自归入提交。正式发布前需审阅、提交对应源码，再使用同一内容的验证与设备验收记录。
- 代码/素材授权仍需项目所有者明确，未自动为既有作品选择许可证。Docker 公网部署和长期实际网络容量测试仍按原审查的后续阶段执行。
