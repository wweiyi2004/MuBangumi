# 项目性能与搬运抽卡审查（2026-10-15）

## 范围与判断

本轮重点追踪「搬进看过的番」、推荐页抽番、收藏加载/编辑/缓存、收藏筛选、统计与导出，以及个人页、好友页的状态订阅。同时检查图片解码边界、静态背景重绘隔离、隐藏标签页的 ticker，以及项目的架构、隐私和固定工具链验证入口。服务端、网站和 Python 研究工具通过现有全仓验证流程检查。

主要瓶颈是主线程上的大对象转换、无必要的重复计算和把后台网络同步纳入界面等待时间。原有渐进候选加载、图片按显示尺寸解码、64 MiB 图片缓存、壁纸重绘隔离及隐藏标签页 TickerMode 已有作用，保留这些机制。

## 已调整

| 区域 | 调整与验证依据 |
| --- | --- |
| 搬运保存 | 每条修改完成本地持久化后更新进度；本地保存完成便释放操作区，远端同步继续运行。慢网络门控测试确认下一张仍可操作；未保存成功的选择保留。批量执行绑定起始修改版本，后来发生的编辑不会被旧选择覆盖。 |
| 卡片运动 | 滑动与飞出方向一致；成功滑动后保留松手位置，不再先弹回中间；复用并释放 CurvedAnimation，尊重减少动画和辅助导航设置。 |
| 封面准备 | 按下一张卡片的实际尺寸预解码，只允许一项预加载在途；快速翻卡时仅保留最新待处理封面，隐藏页面停止安排新预加载。 |
| 连续抽番 | 公共候选页缓存 5 分钟、最多 12 页；可用候选优先复用并避免近期重复。收藏核对结果按账号生命周期短期复用，过期时间不被连续点击延长。切换账号清除个人抽取历史及收藏核对结果，已收藏和隐藏条目仍即时排除。无新结果或失败时保留上一张。 |
| 收藏缓存 | 大 JSON 的解码和模型构造在同一后台任务中完成；大收藏的旧 coverage 读取、模型转 JSON、编码也在后台完成。小数据保持直接处理，避免不必要的 isolate 调度。 |
| 缓存一致性 | 编码开始前即确定写入次序；删除、前缀清除和账号清理与写入共用队列。测试覆盖清理期间旧编码完成、两个并发单条失效操作、调用后源列表被修改、账号之间的缓存隔离。 |
| 收藏筛选 | 按收藏列表引用与筛选条件复用结果；选择状态、更新提示变化不再全量扫描排序。1000 条计数列表测试中，第二次勾选对原始收藏列表的访问次数为 0。 |
| 收藏同步 | overlay 后还要合并本地新修改的路径只在最终结果上排序一次；完整重新加载也在保留新修改后排序。时间比较保留微秒精度，避免反复构造零时刻对象。 |
| 统计与导出 | 500 条及以上统计放到后台，最多一项计算在途，连续切换只保留最新请求，旧账号结果不能替换新账号。月份分布由 12 次遍历改为 1 次；导出连同数据准备和 UTF-8 编码一起后台执行。 |
| 页面订阅 | 个人页和好友页只订阅实际使用的用户/收藏字段，抽番面板不再因无关会话状态变化重建。 |

代码保持现有 JSON schema、4000 条快照上限、coverage 语义、账号命名空间及本地修改队列，不迁移用户数据库，不改写原生 Android 原型或 Shorebird 基线。

## 仍需关注

- 收藏快照仍整包读写；普通 List 写入为保留 coverage 仍会读取旧快照。本轮移除了主线程重计算，但没有声称实现增量数据库或把多次编辑合并为一次落盘。
- 首次抽番在收藏范围未确认时仍需核对收藏；缓存减少后续等待，不能消除首次网络延迟，也不承诺整个目录的均匀抽样。
- 私信和部分社区 HTML 的网络响应解析仍有同步路径，长页面可能产生独立的主线程开销；改动需要连同网站身份检测和旧账号响应保护一起验证。
- 收藏类型串行同步仍是控制请求压力的取舍；完整同步耗时不等同于 UI 卡顿。
- 当前没有手机 profile 帧轨迹或真实账号冷启动测量。布局截图覆盖亮/暗色、320/390/1200 宽及大字体，不能代替设备性能验收。

## 验证入口

定向测试覆盖现有搬运/抽番功能、慢同步下可继续挑选、预加载并发、连续抽取请求数、账户切换、缓存清理与失效排序、统计计算合并及导出 schema。架构检查确认 core/application 不依赖 screens。

全仓回归额外发现共享写入队列会保留已经完成 Future 的调度上下文，混合使用 Widget 的模拟时钟和普通异步测试时会阻塞后续清理。队列现在完成后释放尾部引用，保留异步开始、重入 FIFO 和错误传播语义；增加独立调度域及重入/失败回归。内存快照测试替身也实现了新的原子失效接口，实际 SQLite 路径由并发失效测试覆盖。
