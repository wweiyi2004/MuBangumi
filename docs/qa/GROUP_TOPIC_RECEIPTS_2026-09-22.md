# 小组发帖结果确认

用户报告发帖后提示“发帖结果未知”。这不等于服务端发布失败，不能直接重新 POST。

发现的缺口：P1 返回的帖子 ID 被 `Future<void>` 丢弃；经典网站仅部分响应被当作成功；未知结果与普通失败共用可重发按钮，关闭编辑器后只留下正文草稿。成功也只有一条短暂提示，没有帖子入口。

## 修复行为

- API 与经典网页成功时返回具体的正整数帖子 ID，页面保留“已确认发布”卡片及“查看帖子”。不把空 JSON、`status: ok` 或任意第三方跳转当成回执。
- HTTP 响应丢失、服务端错误、返回编辑表单等保留为待确认。服务端 5xx 即使夹带成员错误代码，也不能触发第二次网站 POST。
- 在发送前，把尝试时间与正文一同存入现有按账号/小组隔离、带版本检查的草稿。待确认状态跨关闭/重启保留，正文暂时锁定，主按钮改为只读核对。
- 核对走当前账号“发表的话题”，绕过本地缓存；限定候选范围，核对账号、小组、标题、原帖正文、创建时间。必须唯一匹配；缺失、歧义或核对失败都不能判定发送失败或自动重发。
- 对旧版本留下、没有尝试时间的普通草稿，提供“核对是否已发布（最近 24 小时）”。保留正常草稿编辑能力，核对不触发人机验证或 POST。
- 明确的服务器拒绝允许修改后提交；未知结果只有用户手工确认未发出后才能恢复编辑。已确认帖子即使草稿清除失败，也尽量先保存回执，避免旧草稿被直接重发。

## 协议依据与边界

已核对官方 [group.ts](https://github.com/bangumi/server-private/blob/master/routes/private/routes/group.ts)：创建成功返回 `{id}`；创建时可以进入审核状态，而普通小组话题列表过滤为正常显示状态。因此“列表看不到”不能单独证明发布失败。

核对最多检查最近 100 条自己发表的话题及 5 个候选详情。已记录尝试的时间范围为尝试前 5 秒到后 5 分钟；旧草稿为最近 24 小时。超过范围、服务端时间偏差、私密内容不可读或审核内容未返回时，继续保留待确认，不伪造回执。

本轮使用合成数据验证响应丢失、唯一/错误/多个匹配、账号切换、重启恢复、存储失败、网页回执与重复提交保护。没有发布真实测试帖，不能从本地测试推断用户之前那篇帖子已经发出。

## 本地验证

针对性测试：`group_topic_submission_test.dart`、`group_topic_composer_test.dart` 及现有社区、持久草稿、身份和网页请求恢复套件。最终结果以 `tool/verify_all.ps1 -Mode Full` 产生的源码指纹报告为准。
