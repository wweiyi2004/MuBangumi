# 好友消息间歇不可用：请求与历史同步恢复

用户反馈好友消息“一会儿可用，一会儿不可用”。已询问当前补丁编号及具体错误，尚未收到现场提示；本次仍沿用此前确认的 `2.3.1+4029` 基线处理，不断言现场已被根治。

## 可复现问题

- 每次消息同步同时扫描收件箱与发件箱，各自首次读取后最多连续翻 100 页。验证完成的监听和返回回调还会启动两次刷新，相同页面请求不合并。
- GET 遇到临时网关错误、连接中断或接收超时立即失败；限流响应没有共享的等待窗口。
- HTTP 200 的异常网页没有消息内容时，被解析为空列表覆盖已有记录；会话详情也可能以空内容替换已有内容。
- Dio 在默认 `validateStatus < 500` 下先抛出 503，应用无法再依据 `cf-mitigated` 分类该响应。先前拦截器直接返回 Response 的用例绕过了实际 HTTP 状态处理，本轮以 HttpClientAdapter 用例复现。

上述五项新增基线回归均在修复前失败。请求量可能放大限流或网络波动，但没有用户现场响应，不能据此断言 Bangumi 已对该用户限流。

## 修改

- 收、发件箱每轮各最多读取三页，较早记录通过现有“继续同步历史会话”入口读取。已读取的旧记录在局部刷新时保留，扫描到末尾后再移除不存在的旧行；退出或切换账号仍立即清除。
- 同一会话快照、路径和查询参数的并发 GET 合并。发送后清除在途读取的复用登记，确保发送后的刷新不会复用发送前请求。
- 登录返回加入监听器已启动的同步，不再重载会话并重复发起一轮扫描。
- 对连接错误、连接/接收超时和常见临时 5xx，等待 600ms 后最多重试一次 GET；重试前检查账号与会话。401、真实挑战和 POST 不自动重发。
- 对 429，以及带 Retry-After 的暂时不可用响应，显示等待提示并暂停同一会话的后续请求；支持秒数、HTTP 日期及无效日期回退。
- 空列表须具有消息列表的页面结构；无法识别的网页返回可重试错误，保留已有数据。无内容且无有效回复表单的会话详情亦返回错误。
- 在完整 HTTP 处理流程里识别 503 挑战页，继续要求用户完成真正的人机验证。

## 验证

新增回归覆盖大历史分批及续读、旧记录保留与移除、并发合并、瞬时及持续网络故障、限流等待、账号切换中止重试、实际 401 / 503 分类、发送不重放和发送后刷新。所有网络测试使用适配器替身，没有向真实好友发送消息。

全量 Flutter 测试 **1,252 项通过**；静态分析无问题，架构边界及图自测通过。已有用户代理绑定、跨账号隔离、真实登录失效、会话更新归属和草稿测试继续通过。三处原先仅返回账号导航的测试样本补上空消息列表结构，以区分真正空列表与不完整网页。

使用原 `2.3.1+4029` 的独立热更新基线，仅移入本轮 Dart 变更。实际补丁编号及服务端回读在发布后记录。
