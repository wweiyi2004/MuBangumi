# 减少重复网页登录验证

本轮针对“软件反复要求补充网页登录”的反馈修改，尚未构建或发布补丁。

## 行为调整

- 已确认的账号与同一份认证 Cookie 绑定，不再因经过 10 分钟而强制重新请求身份核验。重启可复用绑定；旧的未核验记录、切换账号或新 Cookie 仍需核验。
- 计算核验时与当前时刻的认证 Cookie 标识，避免认证 Cookie 过期后，剩余的匿名 Cookie 沿用旧账号身份。捕获新 Cookie 时也必须检查旧绑定仍然有效，才继承核验信息。
- 普通私信、网页入口不再把临时检查失败当成登录要求。主动重试仅重试核验；网络、读取安全存储或页面格式失败不会自动打开补充登录页。
- 401、明确的登录跳转、真实登录表单、官网未登录导航、账号不一致和挑战验证保留相应处理。退出清理失败不会绕过清理流程。
- 429 / 5xx 即使包含登录页 HTML 也按临时错误处理，不清除登录。私信 POST 的服务端错误仍按结果不确定处理，不盲目重发。
- 私信和社区正文里的“请先登录”、登录链接或转义 HTML 不再触发会话过期。缺少网页操作参数、无法识别账号属于可重试错误；身份无法确认时仍拒绝草稿授权和发送。

## 验证

新增覆盖：跨时间与重启复用、明确失效撤销、手动检查断网后复用同一凭据、认证 Cookie 过期而匿名 Cookie 存活、仅捕获匿名 Cookie 时不继承旧绑定、网络/存储失败不打开登录页、正文误判与真实表单识别、503/429 分类。

保留并检查原有账号切换、迟到核验不能恢复退出记录、跨账号草稿隔离、发送结果不确定性等行为。没有访问真实用户 Cookie、代发私信或执行真实账号写入。真实设备上的官网会话过期、验证码与网络行为仍需随安装包复测。

最终 Flutter 全量 1,166 项测试全部通过，静态分析无问题，架构边界检查通过。旧测试中将无法识别账号统一视为必须重新登录的断言，已分别验证“身份未知仍禁止授权，但允许重试”和“明确账号不一致要求登录”；真实退出场景使用官网导航结构作为识别依据。

这是 Dart 层改动，可以作为兼容性验证后的 Shorebird 补丁发布；当前发布的 2.3.1 安装包不会因本地源码变化而自动获得修复。
