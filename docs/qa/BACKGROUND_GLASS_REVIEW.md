# 背景与毛玻璃检查（2026-09-11）

后续状态：用户已授权修正，问题处理及 build 17 验证记录见 [BACKGROUND_GLASS_FIX.md](BACKGROUND_GLASS_FIX.md)。以下保留修正前的检查结果。

结论：自定义壁纸的基础能力可用，但可读性保护、效果预览、材质层级和系统适配尚不完善，不能视为已达到成熟桌面软件的体验要求。本次只检查，没有修改功能代码或用户的背景设置。

## 检查范围与依据

检查 `lib/widgets/app_background.dart`、`lib/state/background_controller.dart`、`lib/screens/background_settings_sheet.dart`、`lib/app.dart`、`lib/screens/home_shell.dart` 及当前短信页的接入。

参考 Windows Acrylic 的用途、可读性与降级建议：
https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic

以 WCAG 2.2 的普通正文 4.5:1、大字 3:1 作为对比度检查基准，不将该局部检查等同于整个桌面应用的合规认证：
https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html

## 优先处理的问题

1. **高：文字缺少稳定的对比度保护。** 开启背景后 Scaffold 全透明、卡片和输入框采用可调低透明度；文字颜色仍由固定浅深色主题决定。默认参数 `glass=0.42, dim=0.32` 下，按实际主题颜色与遮罩合成计算，浅色主题搭配黑色壁纸的卡片正文对比度约为 3.80:1；深色主题搭配白色壁纸，在渐变中段约为 4.04:1。均低于普通正文 4.5:1 基准。直接位于壁纸上的正文在同一测试中仅为 1.35:1 / 1.38:1。模糊不能解决纯色区域的亮度对比问题。应按浅深色设置提亮/压暗遮罩，并为阅读和输入区域设置足够的底色。

2. **高：弹窗与底层内容缺少可靠的视觉分隔。** 当前只对最底层壁纸进行一次 `ImageFiltered`；Dialog、BottomSheet、Drawer 仅被改为半透明，未局部模糊其后方的实际界面内容。遮罩可以压暗下层，但下层文字和卡片轮廓仍可能透出。建议重要确认框、表单默认用实色或高遮挡表面，少量浮层使用真正的局部模糊和实色回退。

3. **中：设置预览与真实效果不同。** 设置页只绘制原图、均匀黑色遮罩和半透明预览卡片，没有模糊滤镜；真实背景使用模糊及随主题变化的渐变遮罩。组件探测确认预览中没有 `ImageFiltered` / `BackdropFilter`。此外滑杆范围为 0–40，实际 sigma 为 `min(value * .55, 18)`，33–40 的效果完全相同。应复用实际渲染组件并修正滑杆映射。

4. **中：全局设置的作用范围不一致。** 标准卡片、顶部栏等通过主题跟随设置；桌面导航的透明度固定为 0.55；短信内容区、输入区使用实色。实色阅读区本身合理，但目前没有明确的分层规则，用户无法从“玻璃不透明度”判断哪些区域会改变。`GlassPanel` 目前没有业务调用，且自身也只是半透明装饰。应明确背景层、导航层、内容层、浮层各自的材质规则。

5. **中：缺少高对比度与减少透明度的回退。** 自绘效果没有接入高对比度、Windows 透明效果偏好或省电回退。`MaterialApp` 也没有单独提供高对比度主题。应先保证高对比度/减少透明度时可切为实色，再评估是否接入系统 Acrylic；不要求所有平台使用同一原生材质。

## 次要交互与实现风险

- 没有一键恢复推荐参数；未启用或未选择图片时仍可拖动三个滑杆，反馈不够明确。即时应用本身是合理设计，不必强制增加“保存”按钮。
- 滑杆每次 `onChanged` 都触发安全存储写入，没有节流或串行队列；启动恢复也没有处理与新操作之间的先后关系。存在磁盘写入过密和状态覆盖的风险，本次没有实机复现持久化错乱。
- 图片安装只确认文件存在并复制，未先验证解码成功；持久化错误仅记录日志，界面仍可能提示“背景已更新”。建议验证导入成功并使保存失败可感知。
- `hasImage` 在构建路径执行同步文件存在检查；应改为缓存已验证状态。未做 GPU 帧时间或大图内存测试，因此不宣称存在已实测的卡顿。

## 已有合理设计

- 默认关闭、自选本地图片、保留原图且可关闭/清除、复制受管理的壁纸副本。
- 图片失效有回退，解码宽度限制为 720–2560。
- 对壁纸单层模糊而非每张卡片都模糊，避免不必要的多层 GPU 成本。可保留这一路径，但产品命名应准确区分“背景模糊”和“面板毛玻璃”。

## 建议调整顺序

先建立内容可读性与弹窗遮挡规则；再统一实际效果和预览、修正参数映射；随后规范各层材质并补充无障碍回退；最后完善推荐预设、导入验证与持久化。建议提供“默认纯色 / 柔和背景 / 轻度毛玻璃”三种模式，高级滑杆作为可选项。
