# 内存占用检查与优化（2026-10-01）

本次保留工作区已有修改、账号凭据和本地数据，使用 `tool/toolchain.json` 指定的 Flutter 3.44.7。未修改平台原生实现、冻结的 Android 原型、Shorebird 基线或依赖版本。

## 检查范围与结论

- 客户端图片：封面、头像、动态附件、BBCode、Markdown 简介、壁纸、分享卡和追番海报。部分展示区域以前直接解码原图；海报预加载也使用原图并一次启动所有请求。
- 临时响应缓存：社区 HTML/JSON 分别最多 400 条，评分历史最多 64 条，条数不能限制单条大型响应的内存。
- 页面生命周期：主导航、发现、社区、消息和个人动态保留已访问标签页；原先未明确关闭隐藏标签页的动画。继续保留页面状态和草稿。
- 列表和控制器：收藏、发现、社区主要列表已有 Sliver/Grid/List builder；详情控制器、RSS/通知计时器、WebView 订阅、番键会连接已有释放逻辑。本次没有为了省内存截断用户收藏、列表或清空草稿。
- 番键会服务：封面下载已有 2 MiB 文件上限，连接和计时器在关闭时清理。打印封面已有解码像素校验、560 像素归一化和双 worker。网站演示组件已有定时器清理。研究用 Python 模型仍未进入客户端。

## 已实现

1. 共享 `bounded_image.dart`：按物理显示尺寸解码，32 像素分桶复用相近尺寸，单边最多 2048 像素。使用 `ResizeImagePolicy.fit` 保持原图比例并禁止放大。覆盖社区/私信/好友/通知/人员头像、动态附件、正文图片、简介、分享卡和壁纸；已有封面控件的上限也由 4096 降为 2048。
2. Flutter 已完成图片缓存上限为 64 MiB、512 项。此限制不包括正在显示的 live 图像、GPU 纹理、WebView 或整个进程。
3. `AsyncCache` 同时按条数和估算内存淘汰 LRU 结果。社区 HTML、JSON 和评分历史各设 8 MiB 预算；超大结果返回调用者但不缓存。估算遍历现有对象，不生成另一份 JSON 字符串。
4. 系统内存告警释放已完成的图片和服务响应缓存。保留在途请求合并和账号切换防护；不触碰持久化离线数据、凭据或写队列，也不创建尚未使用的服务。
5. 所有保留标签页使用 `RetainedTabStack`：隐藏页关闭 TickerMode，暂停动画和动态图像帧处理，恢复时保留状态。
6. 海报预加载与绘制共享 512×768 的解码键，最多同时处理 4 张，避免预加载原图、绘制缩略图产生两份解码缓存。分享卡也预加载有尺寸限制的 provider。

## 验证与效果边界

`test/memory_optimization_test.dart` 实际通过 Flutter 图像解码器验证：1024×2048 测试图片在 64×64 逻辑像素、DPR=2 的展示边界内解码为 64×128，RGBA 缓冲为 32 KiB，原图对应 8 MiB。该结果仅代表此图片解码案例，不能视为整个软件内存降低比例。

回归覆盖字节预算、LRU、超大响应、请求完成时过期回收、内存告警、在途合并、账号变化后的旧响应、标签页动画暂停及状态保留、图片比例、海报键复用与番键会地址切换。另运行社区、私信、个人滚动、背景、分享和海报相关既有测试。

最终统一验证命令：`pwsh -NoProfile -File tool/verify_all.ps1`。结果以 `.dart_tool/verification/<运行编号>/results.json` 和对应日志为准；Quick 流程覆盖 Flutter、服务端、网站、研究工具与架构/隐私检查，不包含设备、发布构建或云端验收。

没有测量真实设备或 Windows 发布进程的优化前后 RSS/私有工作集，不宣称整机内存实测下降。后续可在相同发布版本配置下记录启动、访问全部标签、滚动图片列表、返回首页和后台恢复的 Dart heap、image cache、external memory 与进程 RSS，评估 live 图片和 WebView 的剩余开销。
