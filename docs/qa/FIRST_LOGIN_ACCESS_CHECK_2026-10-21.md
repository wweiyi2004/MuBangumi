# 首次登录功能检测（2026-10-21）

## 需求

首次登录时必须同时具备 Bangumi API 授权和网页登录，才能进入首页；同时在登录流程中逐项检测各功能能否访问。之后的启动不因网页会话过期而拦截，沿用各页面已有的补充验证提示。

## 行为

- 交互式登录（OAuth、令牌、重试已授权的验证）成功后，`SessionState.requiresAccessCheck` 为真，根页面显示 `FirstLoginCheckScreen`。原有 8 秒自动进入首页的计时只影响准备页，不能绕过检测。
- 检测标记按用户 ID 写入 `SnapshotCache`（`session_access_check_pending`，账号作用域）。检测期间退出应用，下次恢复登录仍回到检测页；通过后清除标记，退出登录也清除。标记读取失败时不拦截已恢复的账号。
- 页面外观与首页准备页一致（“欢迎，昵称 / 正在准备你的首页”），不列检测清单：
  - Bangumi 账号（`/v0/me` 用户 ID 与本次登录一致）和网页登录（`AccountAccessController.verify(force: true)`）都通过后自动进入首页，不需要点击。
  - 只有网页登录未通过时停下，显示一句说明和“登录网页版”；返回后重新核验，通过即自动继续。账号核验失败显示原因和“重试”。两种情况都提供“换个账号”。
- 收藏统计、P1 电波提醒、好友动态、私信收件箱的只读检测与必需项并行，用于预热缓存（例如好友动态的网站快照）。必需项通过后最多再等 3 秒，失败或超时都不显示、不拦截，进入后由各页面自己的提示处理。
- 发帖、发送私信等需要 Turnstile 的写入不在检测范围，也不进行任何真实写入。

API 凭据与网页会话仍分别存储、分别核对归属；本功能只把两者作为进入首页的条件。

## 回归验证

- `test/first_login_check_test.dart`：必需项拦截；网页依赖项的阻塞与自动运行；功能项失败与超时可重试；页面全部通过时自动进入、缺网页登录时只提示一次并在登录后自动继续、功能项失败或过慢不显示也不拦截（3 秒后进入）、账号核验失败可重试。
- `test/session_controller_test.dart`：新登录产生检测标记、重启后恢复检测、通过后后续启动直接进入、退出登录清除标记。
