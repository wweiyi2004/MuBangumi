# 消息、发布与加载反馈调整（2026-10-14）

## 行为

BBCode 基础语法参照 [Bangumi 官网指南](https://bgm.tv/help/bbcode)。对齐别名另参考 [站内公开示例](https://bangumi.tv/group/topic/459221)，不将普通 Markdown 标记作为切换渲染器的依据。

- 自我介绍统一使用 BBCode 渲染；Markdown 风格的普通文本不再切换解析器。修复换行、交叉嵌套、开头空行预览，并保留剧透折叠。链接和图片共用地址校验、站内相对路径解析及图片线路设置；裸 HTTP(S) 地址自动生成链接，支持对齐标签别名。
- 新私信先完成本地草稿到发送队列的事务，再返回界面。收件人解析、表单获取和 POST 在队列中处理；发送前核对 API 用户 ID 与网站表单的目标。原有私信回复的即时显示保留。
- 消息标题栏增加发送队列图标，位于好友按钮左侧；手机进入会话后仍可访问。数字仅包含待发送、准备发送和发送中，等待连接、失败、结果待确认另外提示。新私信的未完成任务显示在联系人列表中。
- 发现页、私信联系人及会话、通知、日历和社区列表使用不挡住内容的加载反馈。延迟 300 ms 显示说明，8 秒后补充慢连接提示及可用的重试/官网入口。通知回复摘录按话题完成后逐批发布。好友和历史私信独立展示加载状态，后台自动刷新不展示前台加载提示。
- 初次读取使用静态骨架块，不使用 shimmer。共享淡入时间为 180 ms，遵守系统减少动画和辅助导航设置。刷新及切换分类保留已有内容，旧请求不能覆盖新请求，也不能将旧分类混入新分类的分页结果。
- 小组回复、创建话题及新日志在人机验证和草稿保存完成后关闭编辑器，显示本地发布卡片。卡片跟随单次尝试，按账号、目标和草稿区分；确认的成功再读取服务器内容。失败保留草稿并允许重新编辑、重新验证，结果不确定只能核对或由用户确认未发出后恢复编辑。
- 500 错误后暂未查询到内容，不再自动切换网站接口重复发布。明确的私有小组拒绝仍按既有规则处理。新话题的服务器回执先记录到版本化草稿；未知结果在重启后仍阻止再次提交。日志元数据和回复发送前的已有楼层编号也保存在草稿中，避免把旧内容误认为本次发布结果。

## 验证范围

定向回归覆盖 BBCode 格式、剧透、危险地址、图片线路、空行预览、慢请求反馈、减少动画、部分通知先显示、草稿保存失败、窗口关闭后发送、收件人校验、账号切换后的旧响应，以及拒绝/未知结果恢复。消息标题栏和反馈区域生成 360 px 亮色、暗色截图并检查布局。

测试数据、令牌和收件人均为合成数据。没有进行真实私信、帖子或日志发布，没有测量真机帧耗时。页面反馈优化不代表网络请求耗时变短，也不代表已经消除了全部主线程解析开销。

全项目验证以 `tool/verify_all.ps1 -Mode Quick` 生成的 JSON 和日志为准。此轮不涉及 native 原型、SDK 升级、Shorebird 基线或发布打包。
