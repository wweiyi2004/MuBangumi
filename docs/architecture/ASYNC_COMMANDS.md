# 异步交互与本地命令队列

2026-09-18，针对用户反馈的私聊输入与发送延迟实施。

## 已落地

- 输入：草稿文本仍逐次更新模型，但只有保存状态、错误、就绪状态发生变化才重建草稿外层；不再每按一个键都重建整块聊天界面。
- 私聊回复与新私信：先把不可变命令和草稿清除一起提交到本地 SQLite，再清空对应输入 / 关闭写信页。网络工作由应用级队列继续执行，切换联系人不改变已入队消息的收件人。
- 私聊队列持久化在原有草稿数据库的新表，原草稿表保持兼容。应用关闭时未完成的任务在下次启动后按当前登录账号恢复。
- 收藏、进度仍使用现有 `BangumiSyncStore` / `PendingSyncController`：它们是可覆盖的目标状态写入，沿用其合并和重试策略。
- 数据读取继续异步并行；新私聊入口和返回联系人不等待所有历史页完成。联系人合并按数据快照复用，日期排序值每次合并仅计算一次。

## 私聊命令的边界

- 命令绑定已验证的账号、收件人、会话和讨论目标。执行前重新获取表单，并核对收件人、相关话题；不持久化 Cookie、Token、formhash。
- 同一收件人保持 FIFO，前一条失败或结果不确定时暂停后续消息；其他收件人可以继续。
- 状态：待发送 → 准备发送 → 发送中 → 已发送；另有等待连接 / 登录、失败、结果待确认、取消。
- SQLite 原子认领与 attempt 编号阻止旧执行器覆盖新一轮任务。草稿版本校验和源版本唯一约束防止重复本地入队。
- 崩溃时的准备阶段可以恢复；已经开始 POST 的任务变成“结果待确认”，不自动重发。
- 网络超时、服务端 5xx、POST 后的身份状态异常都不当作“确定没发送”。支持回读会话核对，仍不能确认时由用户决定是否重发。Bangumi 没有本次流程可用的幂等键，不能宣称网络层严格 exactly-once。
- 已完成记录保留最近约 100 项，未完成任务不清理。队列入口在消息页，支持查看状态、复制内容、取消未开始的任务、重试或核对。
- 草稿备份导出按 `pm_draft` 行工作，不导出发送队列，避免恢复旧备份后自动重放已发送命令。

## 全应用采用同一原则，但按操作语义执行

读取、搜索和详情加载不串行排入写入队列；可缓存、合并相同请求，丢弃过时结果。收藏与进度是幂等目标状态，可合并最终意图。私信是不能随意合并的追加消息，需要保序并处理不确定结果。小组发帖、动态等目前仍保留原有提交与人机验证流程，本次没有把时效性验证码存入队列后盲目重放。

## 验证

- 真正的 SQLite 测试覆盖入队与草稿清除同事务、重开数据库、旧版迁移、版本冲突、每收件人顺序、崩溃恢复、账号隔离、旧 attempt 不能影响新执行器。
- 控制网络不返回的测试验证：回复入队后能继续输入；新私信入队后可以离开页面；切换联系人后仍发送给原目标。
- 队列测试使用实现队列接口的内存仓库；生产使用 `PmDraftStore`。旧的仅草稿仓库实现保留原有直接发送兼容路径，其回归测试不能代替新队列测试。
- 未向真实联系人发送测试消息。
- 验证结果：101 项原有及队列回归通过，随后新增目标变化拒发用例通过；最终针对队列、存储和布局的 26 项检查通过。19 个相关模块静态检查通过。
- Windows Release 构建通过，已启动新版供用户本地检查输入与发送体验。

## 本机计算基准

合成 1000 位好友、8000 条会话，Dart VM 预热 5 次、测量 25 次中位数：合并计算由 560463 微秒降至 2770 微秒。诊断脚本及旧实现快照位于本机 `.dart_tool/pm_contacts_benchmark.dart` 与 `.dart_tool/pm_contact_before.dart`，不是产品资源。该结果衡量本地合并计算，不是线上请求耗时或用户端实际送达时间。
