# Android 登录恢复与本地数据修复（2026-09-22）

用户确认主要在 Android 手机遇到反复验证、私信/小组加载失败，以及发送或回复失灵。本轮在现有未提交改动基础上修复已确认路径，没有发布补丁、发送真实私信或向小组提交测试内容。

## 登录专项结果

### 1. 普通刷新无法从临时存储故障中恢复

原来安全存储读取失败后，普通业务请求只检查内存中的 unavailable 状态；即使存储已恢复，私信刷新也不再读取，只有设置页的强制核验能恢复。

现在普通请求会重新读取，多个并发请求共享一次恢复。读取成功且已有有效账号绑定时直接复用，不额外探测首页；持续失败仍保留登录记录并报告暂时不可用。

### 2. 首页正常掩盖私信或小组页面的验证要求

原来点击补充验证会强制探测首页。如果首页可以正常访问，而 `/pm` 或小组页面仍被要求验证，应用就直接返回业务页，形成重复失败。

现在真正的 challenge 状态进入交互恢复，私信和小组服务会记录实际受阻的 GET 页面。恢复地址仅接受 `https://bgm.tv` 的普通页面；私信提交的恢复指向 `/pm`，小组回复指向话题页，不打开提交接口重放写操作。

### 3. 网页验证未完成时提前退出

原来即使当前 WebView 显示验证页，只要 Cookie 仍在、独立首页请求成功，就会保存会话并自动退出。页面尚在 loading 或 JavaScript 证据暂不可读时也有此问题。

现在补充登录界面必须读取当前网页的账号导航。挑战页、未就绪页面或缺少浏览器证据时继续等待；登录成功后核对官方来源、当前页面、前后认证 Cookie 和应用账号，再恢复业务。Android 原生 Cookie 读取继续保留 HttpOnly 登录 Cookie。

### 4. 两次核验可能产生相同的请求标识

请求标识原来依赖 Cookie 与时间等序列化字段。同一时刻核验相同 Cookie，可能得到相同标识，导致旧响应被误认为属于刚恢复的登录。全量回归中的快速连续核验也暴露了这一边界。

每次成功核验现在获得独立随机标识并持久化。相同时间的续期也能区分；JSON 往返保持标识稳定。旧版有效绑定保持兼容，认证 Cookie 的账号/草稿归属规则不变。

### 5. OAuth 授权与补充网页登录没有共享完整的浏览器上下文

原来补充网页登录已能保存 User-Agent 和网页身份，但 OAuth 授权只传递 Cookie。Android 完成一次登录后，网站核验仍可能使用应用默认请求身份。

现在两个入口复用网页身份捕获逻辑。Android 在接收授权回调、离开官方页面前捕获浏览器身份，并与 Cookie 一起传递到账号验证。只有网站导航账号与已验证的 API 账号一致时才建立绑定；否则保持未核验。临时 `/me` 失败后的重试也保留该捕获上下文。

这项改动确认修复了上下文传递缺口，不将模拟测试中的 User-Agent 一致等同于所有真实站点挑战都已解决。

### 6. 小组编辑器缺少就地恢复入口

小组网站通道的缺少登录、登录到期和网页挑战现在使用明确的错误类型。编辑器展示“补充账号验证”，恢复前保存草稿、保留当前输入。恢复成功后需要再次点击发送并获取新的验证码，不自动重发之前的 POST。

## 首轮三个数据缺陷

- “下一集”读取完整章节列表再保存共用快照；进度计算仍只统计本篇，SP/OP/ED 及其状态保留。
- 停止上传失败记录只使对应作品的快照失效，其他收藏保留，并标记快照为部分数据。服务器刷新成功后恢复该作品。
- RSS 响应返回后重读当前绑定，最终插入事务再次检查有效绑定和标题匹配，避免解除绑定后产生迟到的新提醒。

原始审查与失败输出保留在 [首轮报告](BUG_AUDIT_2026-09-22.md)。原复现入口现在转到默认测试中的永久回归用例。

## 验证与边界

- 最初三个登录复现分别确认：存储恢复后普通请求仍失败、主页探测跳过交互恢复、挑战页面提前自动完成登录。
- 全量 Flutter 测试 1,299 项通过；随后补充 loading / 缺少浏览器证据两个场景，与登录、OAuth、私信请求恢复、社区编辑器、收藏和 RSS 的相关测试共 106 项全部通过。
- 全量静态分析通过；最后修改的页面及新增用例再次分析通过；架构边界与依赖图自测通过，251 个 Dart 文件无 import/export 环。
- Android arm64 Debug 编译通过，产物 `build/app/outputs/flutter-apk/app-debug.apk`。这是本机编译验证，未安装到设备、未发布；构建日志为 `.dart_tool/login_fix_android_build.log`。
- 新增默认测试：`test/login_recovery_regression_test.dart`、`test/data_consistency_regression_test.dart`；扩展 OAuth 和社区编辑器测试。既有会话失效、账号切换、迟到请求、不确定发送结果等回归继续通过。
- 本机没有连接 Android 设备；WebView 页面交互通过模拟平台接口验证，共用账号/网络/持久化逻辑通过隔离测试验证。尚无真实 Android 账号的登录、收发件及小组操作结果。

本地过程日志：`.dart_tool/login_recovery_before.log`、`.dart_tool/login_fix_tests_final.log`、`.dart_tool/login_fix_verification.log`、`.dart_tool/login_fix_analyze_final.log`。测试仅使用虚构凭据、内存数据库和模拟 HTTP 响应。

## 上游核对

核对了 [Bangumi 当前认证错误定义](https://github.com/bangumi/server-private/blob/master/lib/auth/index.ts)以及[验证码/小组错误定义](https://github.com/bangumi/server-private/blob/master/lib/error.ts)：凭据失效、验证码失败和成员权限错误必须分别处理，本轮保留既有分类。此处是源码核对，不代表已测过线上部署的每一种响应。

Cloudflare 的[验证通过凭据说明](https://developers.cloudflare.com/cloudflare-challenges/concepts/clearance/)也说明凭据与访问者及设备相关。浏览器上下文应完整保留，但遇到真正挑战仍由用户在官方页面完成。
