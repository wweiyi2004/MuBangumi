## 后续两轮复核

用户要求再次检查后，分别做数据源/解析对照和入口/阅读回归两轮复核。

### 第一轮：官网、P1 与回退

重新匿名读取条目话题 32382、小组话题 371849 的 HTML 和 P1，以及条目 328609 的两页吐槽。原始数据保存在忽略目录 `.dart_tool/website-parity-audit/recheck-*`，不进入仓库。

- 条目话题：HTML 6/6，P1 6 条，标题、ID 与楼层对应。
- 小组话题：HTML 4/4，P1 4 条，标题、ID 与楼层对应。
- 吐槽：两页分别 20/20，合计 40 个唯一 ID，没有因解析造成丢项或翻页重复。

新增回归先复现了 4 个失败用例，确认并修复两个遗漏：

1. P1 话题响应缺少 `replies`、为空或含无正文的占位行时，不能作为成功话题。条目和小组都检查有效楼主正文；条目回退页面如果是登录/挑战/空内容，明确报错。账号切换后旧请求不得开始新账号下的回退读取。
2. HTML 回退中的 `.smile` 图片按内联表情渲染，保持 22 高度，避免作为普通正文图片放大。

### 第二轮：通知、分享与长内容

- `CommunityTopic.targetPostId` 贯穿通知和分享入口；打开后定位到目标回复，兼容 P1 数字 ID 与 HTML `post_ID`。找不到目标时说明可能删除或不可见，仍可去官网核对。
- 初始定位不覆盖保存的阅读位置；后续刷新不强制再次跳转，旧账号的延迟结果不能操作新账号页面。
- 分享保留 `#post_ID`，兼容小组、条目、章节、人物和角色的讨论入口及长短 `rakuen` 路径。人物/角色没有楼层锚点时继续打开资料页。
- 扫码回归发现楼层锚点被 URI 编码为 `%23`，已补上受限 GitHub 下载页二维码片段的解码及往返验证。继续保留域名、端口、路径与编号校验。
- 长吐槽使用原地展开全文，作者资料入口保留；评论行按 ID 区分，刷新后不会把一人的展开状态套到另一人。
- 再检查错误恢复时确认：工具栏刷新已强制读取，但错误页/加载提示的重试原先仍使用普通缓存。新增用例先复现“点重试后仍留在错误页”，再统一为 `refresh: true`，使网络或官网页面恢复后能立即重试。
