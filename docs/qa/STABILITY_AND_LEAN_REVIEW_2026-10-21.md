## 确认并修复

- **旧吐槽解析漏项和元数据不一致**：旧正则依赖头像字段，并在缺少它时丢失评论；实体、换行的处理也不同。统一使用已有的 HTML DOM 解析，一条结构化解析路径同时支持当前官网与旧 `item_ID` 布局，保留无头像评论、真实 ID、评分、实体和换行。
- **虚构评论 ID 导致跨页误去重**：纯文本回退原先使用从 0 开始的页内序号，后页会与前页碰撞。没有服务端身份时统一使用 0 表示未知，沿用控制器已有的未知 ID 不去重规则。
- **多个无 ID 评论造成重复 Widget key**：只给有真实 ID 的评论设置稳定键，无 ID 评论仍可正常展示；组件内容变化时重置展开状态，避免复用上条评论的展开状态。
- **异常评论容器被误判为空**：有评论行却无法识别正文时报告解析错误，合法空容器才返回空列表。
- **无替代文字的官网表情消失**：直接复用现有图片组件读取表情源，显示在 44 × 22 的内联区域，不再依赖 `alt` 恰好对应表情别名。
- **HTML 递归没有深度边界**：与现有 BBCode 的深度限制保持一致，HTML 超过 32 层时省略深层内容并提示，避免无界递归；不把被省略的剧透改成裸文本。
- **正文在重复布局时重新解析**：富文本状态仅保留当前正文的一棵解析树，正文或格式变化时替换；没有增加全局缓存。格式切换、剧透和链接回归保持通过。
- **个人数据库遇到短暂锁竞争立即失败**：首轮全量测试的崩溃恢复用例在 `journal_mode` 配置处遇锁；单跑该用例可通过，但独立双连接回归能复现“另一连接只持锁 150 毫秒，打开仍立即失败”。新增共用配置，先设置 SQLite 原生 `busy_timeout=5000`，再设置原有 DELETE 日志模式；六个个人数据仓库和备份协调库复用它。没有增加 Dart 重试循环、重放写入、修改日志模式或新增数据库。依据：[SQLite 锁等待文档](https://sqlite.org/c3ref/busy_timeout.html)。

修改前的针对性用例分别复现了解析失败、虚构 ID、伪空结果、重复 key、展开状态沿用、无标签表情缺失；深层 HTML 测试验证新增资源边界，格式切换测试防止解析树复用引入旧格式残留。
