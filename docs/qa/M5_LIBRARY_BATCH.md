# M5 收藏批量整理验收记录

日期：2026-09-08。实现及自动化验证完成，未发布。本阶段没有上传 GitHub Release 或 Shorebird 补丁。

## 交付行为

- 收藏页提供“批量整理”，可点选作品、全选当前结果、清空和退出。选择在切换搜索／类型／状态筛选时保留，并显示筛选外的已选数量；长按仍可查看完整名称。
- 执行前展示账号、数量、作品类型、预计修改数及完整作品清单。批量状态支持计划中、进行中、已完成、搁置和抛弃；补齐本篇进度默认关闭，只有明确开启时才作用于动画／三次元。
- 批量状态使用官方 `PATCH /v0/users/-/collections/{subject_id}`，请求体仅含 `type`，不会重写评分、吐槽、标签、隐私或书籍进度，也不会自动重新创建官网已删除的收藏。接口语义见 [Bangumi 官方 OpenAPI](https://github.com/bangumi/server/blob/master/openapi/v0.yaml)。
- 状态修改逐项保存到既有离线队列，本轮保存结束后集中启动同步。重复点击不会重复派发；一项本机保存失败不影响其他项，可只重试失败项。
- 新番表批量加入可选择 1990–2100 年、季度及星期／待安排，固定目标季度，一次保存该季度数据并续排提醒。已有条目保留星期、顺序、备注和提醒；新条目默认关闭提醒，不切换正在查看的季度。
- 结果分别显示本机已保存、未修改、保存失败和未开始。上传状态复用同步问题入口，并标明该入口包含账号的其他待同步修改。本机已保存不等于服务器已经接受。
- 返回或停止会结束当前保存后停止后续项目；返回收藏页时只移除已处理的选择，保存失败及未开始项保留选择。账号变化后不再派发新项目，也不显示原账号的批量内容与同步问题。

## 数据与重试保护

每个批量计划绑定账号和本次会话，条目绑定执行时的本地修改版本；较新的本地修改不会被较旧计划覆盖。请求发出前、等待凭据刷新后和准备重试时都会再次检查账号条件。

批量状态使用独立队列键，避免替换已有的完整收藏编辑。较早的章节完成操作保留在原队列位置，之后的取消单集或状态变化仍按顺序执行。

同步数据库升级至版本 3，保存每个账号／作品最近的修改、收藏及完成操作版本。即使较新操作已上传并移出队列，旧失败记录也不能重试覆盖它。过时记录保留在问题列表中供核对，可以停止上传；丢弃过时记录不会清除较新的缓存与撤销状态。

重启后继续处理原账号已经落盘的待同步记录；执行界面的未开始选择属于当次界面状态，不能把尚未保存的项目显示为已完成。
