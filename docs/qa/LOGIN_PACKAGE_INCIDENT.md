# Windows 发布包账号缓存事件

日期：2026-09-11。GitHub 附件撤回已执行；初次本地修复记录如下。独立 2.1.2 修复分支与 GitHub 草稿的后续进度见文末。

## 证据与范围

- 用户反馈 v2.1.0 Windows ZIP 解压运行后显示开发者账号。
- 已核对该 ZIP 的 SHA-256 与 GitHub 附件摘要完全一致：`9b006c75a3b21972974f20a423cf3e5a0d33d1cd3ed46e9ad20c62455de73a29`。
- ZIP 包含 `.dart_tool/sqflite_common_ffi/databases/` 下的 5 个 SQLite 文件。其中包含开发测试账号身份、515 条收藏快照及本地新番表记录。
- 原启动代码在发现任意本机凭据后先读取 SQLite 的 `session_last_user`，再请求 `/me`；临时验证失败可保留该界面。因此用户自身凭据可能与包内开发者缓存错配。无本机凭据时该代码仍会进入登录页，尚未在全新 Windows 用户环境完成真机复现。
- 已确认的是本地数据外发。没有据此认定用户获得了开发者的有效登录凭据；本次没有使用外发数据发起账号访问或写操作。

## 修复行为

1. `/me` 成功后，将已验证身份绑定到当前安全存储凭据。读取时要求凭据匹配；更换 OAuth/个人令牌及退出清除绑定，刷新时与新凭据一起保存。
2. 启动只恢复安全存储中绑定的身份，不以 SQLite 的 `session_last_user` 决定账号。旧版记录没有绑定时先联网核验，断网保留凭据并提供重试；不能借包内缓存进入另一账号。
3. Windows 可丢弃缓存改用应用用户目录中的 `cache-v2/mubangumi.sqlite`，不读取或导入旧可执行文件旁的缓存。其他平台缓存升级时清除未绑定时代的账号缓存。新番表、草稿、RSS 配置和待同步修改等独立持久数据不删除；旧目录保留供后续按需备份导入。
4. 已有的授权验证续试与缓存先展示改动保留，并调整刷新启动顺序，防止恢复旧 Token 覆盖刚刷新的 Token。旧凭据记录损坏时仍允许新登录修复。
5. 打包继续从独立暂存目录按运行文件范围复制，并检查暂存目录与最终 ZIP：拒绝数据库、浏览器资料目录、凭据文件、异常路径、重复项和链接；检查文件头以拒绝改名的 SQLite 文件。最终校验通过后才将临时归档命名为可分发 ZIP。
6. 新增 PowerShell 回归和 CI 触发路径。独立核验命令：

```powershell
.\tool\verify_windows_package.ps1 -ArchivePath <待检查的Windows.zip>
.\tool\tests\windows_package_safety_test.ps1
```
