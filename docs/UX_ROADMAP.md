# MuBangumi 长期体验改进计划

创建日期：2026-09-08。状态：M1–M3 实现及自动化验证已完成，官网与真机验收待补；下一步 M4。

## 目标与基线

完成七项已讨论的体验改进：私信草稿、观看进度撤销、首页作品置顶、手机新番表列表视图、番会荐反馈、收藏批量整理、本地备份与导入。

主线为 Flutter。优先验证 Android 手机和 Windows；iOS 共享代码的编译、签名与真机验证单列记录。`native-android/` 保持冻结原型状态。

规划基线为本地提交 `51669c9`，最近一次全量验证为 440 项测试通过。已发布基线为 `v2.1.1 / 2.1.1+11`。下面这些工作已经本地完成，继续保留回归测试，不重复开发：

- 私信收件人、话题切换和网站会话隔离修复，Windows Cookie 清理顺序修复。
- 长名称展示与展开、大数字统计、统计直达收藏。
- 首页与收藏页的待同步状态和问题入口。
- 首页查看全部、最近搜索、收藏筛选与排序记忆。
- 推荐加载失败、部分结果与无匹配的区分及重试。

上述未发布改动见 [CHANGELOG](../CHANGELOG.md)。实现、验证、提交和发布分别记录；本地功能完成不代表线上已更新。

## 推进方式

按六个功能里程碑推进，每轮交付一个能独立使用、检查和回退的增量。每轮结束更新本文状态、测试证据和提交号，再进入下一轮。具体日期根据实现和设备验证结果安排。

| 阶段 | 交付内容 | 主要依赖 | 状态 |
| --- | --- | --- | --- |
| M0 | 盘点基线、建立任务与验收清单 | 当前代码与检查记录 | 已完成规划 |
| M1 | 私信草稿自动保存与恢复 | 账号身份、私信表单与持久化存储 | 实现及自动化验证完成；官网／真机待验 |
| M2 | 单集进度撤销、首页置顶 | 离线队列、章节快照、账号偏好 | 实现及自动化验证完成；真机待验 |
| M3 | 手机新番表“今日／本周”列表 | 现有新番表、提醒与 RSS 数据 | 实现及自动化验证完成；真机待验 |
| M4 | 番会荐“不感兴趣”与恢复入口 | 现有规则推荐、本地偏好 | 待开始 |
| M5 | 收藏批量改状态、批量加入新番表 | 同步队列、操作反馈；复用 M2 的操作保护 | 待开始 |
| M6 | 本地备份与导入、整体交付验收 | 前面各阶段的数据结构稳定 | 待开始 |

M1、M2 优先。M3、M4 可在不影响前置功能的情况下调整先后。M6 最后实施，保证备份覆盖新增数据。遇到设备或官网验证暂不可用时，明确标注待验证，并继续可独立开展的工作。

## M1：私信草稿

**用户结果**：离开写信页或重新启动应用后，可以继续写；进入另一会话时不会出现上一会话的文字。

- [x] 明确新建短信与会话回复的草稿模型、账号归属、草稿 ID、收件人和话题标识。
- [x] 沿用社区草稿的防抖、顺序写入和迟到请求保护模式，增加私信专用字段与存储。
- [x] 新建短信恢复收件人、标题和正文；回复草稿绑定具体会话／话题。
- [x] 正常返回、切后台时补存；发送失败保留，发送成功后顺序清除。
- [x] 保存失败提供可见反馈和重试，不把未落盘内容显示为已保存。
- [x] 实现网站会话与草稿账号的关联核验。身份无法确认时先保留草稿并完成核验，禁止自动跨账号恢复；恢复草稿不会直接发送短信。

实现与验证记录见 [M1 验收记录](qa/M1_PRIVATE_MESSAGE_DRAFTS.md)。以上勾选表示实现完成；官网实际登录、手机系统杀进程及原生键盘验收仍单列待办，不代表已发布。

验收：输入停止并完成保存后，模拟进程重启，草稿字段完全一致；改收件人、切换话题、重复打开、保存／发送失败和账号切换均有回归测试；发送后的迟到保存不能重新生成草稿。进程重建与持久数据恢复分别验证，参考 [Android 状态保存指南](https://developer.android.com/topic/libraries/architecture/saving-states)。

主要入口：`lib/screens/pm_page.dart`、`lib/core/network/pm_service.dart`、`lib/core/storage/community_draft_store.dart`。

## M2：进度撤销与首页置顶

**用户结果**：误点进度可以纠正，最常追的作品可以稳定地出现在前面。

- [x] 首版撤销覆盖“下一集看过”和单集点格子，提示明确显示作品及章节。
- [x] 提供“撤销”入口，默认保留约 10 秒，并适配无障碍阅读所需时长；交互参考 [Material Snackbar 的撤销模式](https://github.com/material-components/material-components-android/blob/master/docs/components/Snackbar.md)。
- [x] 撤销同步更新本地快照与待同步操作，校验账号、对象及操作版本；重复点击无副作用，不能覆盖后续的新修改。
- [x] 首页提供置顶、取消置顶和调整顺序入口；置顶顺序按账号持久化。
- [x] 置顶只影响首页顺序；已完成或已移除的作品退出“继续追”，首页预览和查看全部的计数保持一致。

实现与验证记录见 [M2 验收记录](qa/M2_PROGRESS_AND_PINS.md)。账号隔离、队列迁移及渲染回归已覆盖；实际设备与线上服务组合仍待验收。

验收：联网、离线、上传途中、上传完成后、再次修改同一集及账号切换时撤销结果正确；重启后置顶顺序不变，同一作品不重复显示。先支持最近一次有效操作，避免引入未经验证的多步撤销链。

主要入口：`lib/state/session_controller.dart`、`lib/core/storage/bangumi_sync_store.dart`、`lib/core/storage/snapshot_cache.dart`、`lib/widgets/episode_grid_sheet.dart`、`lib/screens/home_page.dart`。

## M3：手机新番表列表视图

**用户结果**：手机打开新番表，能清楚看到今天安排了什么、当前进度及提醒时间。

- [x] 增加“今日／本周”列表，与现有周表切换；手机首次使用默认今日列表，Windows 默认周表。
- [x] 记住用户选择的视图；切季度后使用对应季度的数据。
- [x] 列表展示可读名称、观看进度、提醒状态和常用操作，复用同一份新番表数据与操作入口。
- [x] 处理跨午夜、恢复前台、时区变化及当天没有安排的状态。
- [x] “今日安排”和 RSS 已确认更新分别表达；周表海报导出继续使用现有排版。

实现与验证记录见 [M3 验收记录](qa/M3_SCHEDULE_LISTS.md)。自动化包含 320×640 手机操作、三视图切换和日期／时区边界；实际系统提醒送达仍需设备验收。

验收：320、390、1200 宽度以及 1／1.8 倍字体均可操作；移动安排、关闭提醒、移除作品后，列表、周表和提醒状态一致；空季度与跨日不会显示过期内容。

主要入口：`lib/screens/schedule_page.dart`、`lib/state/schedule_controller.dart`、`lib/state/rss_controller.dart`、`lib/core/notifications/schedule_reminder_service.dart`。

## M4：推荐反馈

**用户结果**：点过“不感兴趣”的作品不会反复出现，误选后可以恢复。

- [ ] 推荐卡片增加“不感兴趣”，立即移出本次结果并按账号保存。
- [ ] 新一轮推荐继续排除已反馈作品；继续保留已收藏作品排除规则。
- [ ] 提供查看和恢复隐藏作品的入口。
- [ ] 默认反馈只针对该作品。若增加“少推荐同类”，使用独立、明确的选项和可恢复设置，不根据一次反馈大幅改变全部偏好。
- [ ] 保留推荐原因、部分失败与重试提示，处理过滤后无结果的情况。

验收：重启、重新检索、切换账号后反馈范围正确；恢复后作品可以重新进入候选；新增过滤不会影响未反馈用户的原排序。采用现有标签与评分规则实现，ALS 训练工具接入作为独立后续课题。

主要入口：`lib/screens/fan_recommend_page.dart`、`lib/core/recommend/fan_recommend_engine.dart`、`lib/core/storage/browsing_store.dart`。

## M5：收藏批量整理

**用户结果**：季末整理一批收藏时，不必反复打开每个条目。

- [ ] 增加可发现的多选入口、已选数量、取消选择与退出模式。
- [ ] 首版支持批量修改收藏状态、批量加入新番表；标签扩展另行迭代。
- [ ] 执行前展示影响数量、目标状态、加入的季度／星期，以及是否补齐章节进度。
- [ ] 保留未修改字段；用现有离线队列保存操作，提供清晰的已保存、待同步和失败结果。
- [ ] 限制并发，重复点击不重复派发，重试只处理失败项；账号切换停止派发未开始的操作。

验收：1 项、50 项和混合作品类型的批量操作均有测试；单项失败不导致整批结果丢失；未选中作品不变；断网和重启后可继续处理原账号的待同步记录。

主要入口：`lib/screens/library_page.dart`、`lib/state/session_controller.dart`、`lib/core/storage/bangumi_sync_store.dart`、`lib/state/schedule_controller.dart`。

## M6：本地备份、导入与整体交付

**用户结果**：换设备后，可以恢复自己的追番安排与偏好，并明确知道导入了什么。

- [ ] 建立带版本、账号身份、导出时间、数据种类和校验信息的备份格式。
- [ ] 覆盖新番表、RSS 订阅与过滤规则、备注／屏蔽、置顶、浏览偏好和推荐反馈；草稿作为可选类别，私信草稿默认不勾选。
- [ ] 登录凭据、Cookie、可丢弃缓存和可重放的待同步队列不进入备份。导出前说明仍有多少修改尚未同步。
- [ ] 导入先校验版本、账号、结构和大小，再显示数量及冲突预览，明确合并／覆盖行为。
- [ ] 导入本地数据不会自动向 Bangumi 批量写入收藏或进度。
- [ ] 使用可恢复的导入日志或回滚快照，处理损坏文件、重复导入和中途退出；压缩包路径必须限制在导入暂存目录内。
- [ ] 完成 Android 与 Windows 的备份互导、全功能回归和可安装产物验收。

验收：导出后在空白测试环境导入，所选数据类别的数量和关键字段一致；账号不匹配、未知格式或损坏备份不会改动现有数据；模拟写入失败与进程中断后可恢复；测试包与发布包中没有用户数据库和凭据。

主要入口：各 `lib/core/storage/` 仓库、`lib/screens/profile_page.dart`、现有文件选择／分享能力、`tool/build_release.ps1`、`tool/package_windows_release.ps1`。

## 每阶段共同验收

1. 先固定业务行为与失败场景，再完成实现和有意义的回归；修复原有测试，不削弱它们来迁就新行为。
2. 必须覆盖适用的账号切换、慢请求、失败重试、连续操作、后台／重启恢复与本地数据隔离。
3. 涉及界面的阶段检查浅色／深色、320／390／1200 宽度、1／1.8 倍字体，核对真实字体渲染；新增主要触控入口以至少 48dp 触控区域为目标，参考 [Android 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views?hl=en)。
4. 定向测试通过后运行适当的全量检查；记录 `flutter analyze --no-pub lib test` 和 `flutter test --no-pub` 的实际结果。测试数量随新增场景增长，不把基线数量当作完成标准。
5. 真机记录冷启动、恢复前台、滚动和关键操作耗时；首次测量建立基线，后续优化必须有可比较的证据。没有设备验证时明确标注，不能写成已通过。
6. 更新变更说明、此计划的状态和本地提交；阶段验收包标明包含的功能、版本及验证范围。发布时继续核对 Android 签名、版本号、Shorebird 基线、Windows 运行资源和附件哈希。

完成定义：七项功能均满足各自验收；跨功能、账号及备份回归通过；Android／Windows 可安装产物已验证；文档、提交及发布状态可追溯。不能仅因为写完界面或测试数量增加就把阶段标为完成。
